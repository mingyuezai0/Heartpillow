        心枕

        v0.9.3

        心枕是一款跑在本机的 AI 陪伴应用：以人设、记忆与话语规范为核心，让一个角色在对话、QQ、B 站里保持连贯、像真人的语感。角色资料与聊天记录默认只存在本地浏览器，连不连外网、连哪个模型，都由你决定。

        概览

        心枕由四块组成：对话（和她聊天）、人设（她是谁、记得什么、在计划什么）、外接（QQ / B 站）、名单（谁能被她认真对待）。

        • 本机优先：人设、记忆、聊天记录都存在你这台机器的浏览器里；清缓存前记得导出。
        • 模型自选：任何 OpenAI 兼容接口，或 Anthropic 的 Messages 接口都能接。
        • 外接可选：只在本机聊天也完全可用；接 QQ / B 站是为了让她在别处也活着。
        提示　下面所有命令里的 8.156.81.219、7863、2821744520 都是示例，换成你自己的服务器 IP、端口和机器人 QQ 号。

        快速开始

        1. 填接口

        左侧「设置 → 模型接口」填三样东西：接口地址（填到 /v1 为止）、API Key、模型名。

        接口地址   https://api.deepseek.com/v1
API Key    sk-...
模型       deepseek-chat

        然后点「测试连接」，能出一句话就说明通了。

        2. 立人设

        「人设 → 人设」里写她的名字、你怎么称呼她、她怎么称呼你、身份处境、说话方式。写得越具体，她越像那个人。

        3. 开始聊

        回到「对话」直接说话。她会按你设的篇幅和分条规则回复；长回复会拆成几条短消息发出来，像真人在手机上打字。

        对话

        • 重新生成：鼠标移到她的回复上，点刷新图标可以从那条重来（后面的对话会删掉）。
        • 附件：图片、文件可以直接拖进输入框；图片会一起给模型看。
        • 来源标记：每条消息旁边有个小标签 —— 心枕 / QQ / B 站，标出这句话从哪儿来的。
        • 隐藏指令：她会在回复末尾写一段你看不到的记录（[[记忆]]…[[/记忆]]、[[计划:…]]、[[情绪:…]]），用来更新记忆、计划和情绪，正文里不会出现。

        人设

        基础模板：第一次打开心枕，人设里就是「大肥鱼」这套（女仆、鲸鱼娘）。它也在「套用模板」里，随时能套回去 —— 模板只带人设本身，不带记忆、关键词、梗知识和计划。

        人设下面有 形象 / 人设 / 记忆 / 计划 / 日记 / 表情包 / 梗知识 / 我 几个页签，都和当前角色绑定，切换角色就是换一整套。

        记忆

        • 关键记忆：生日、忌口、家人、约定、伤疤这类，忘了会很伤人的事。
        • 轻度记忆：今天吃了什么、天气、随口提的小事，只留 7 天；过期的按「整天」合并成一条关键记忆存着。
        • 每条都带完整时间（年-月-日 时:分:秒）；「整理一次」可以立刻从最近的对话里再提炼一遍。
        • 自动整理：在对话里每两轮一次；QQ / B 站回完也会顺带整理；打开页面时如果发现新消息，会补一次。

        记忆、计划与梗

        这三件事都是她自己做的，你不需要手动维护：

        记忆

        • 聊天里聊到的关键事（名字、口味、重要约定）会自动变成「关键记忆」，随口一句小事进「轻度记忆」；
        • 轻度记忆只保留 7 天，过期的会合并成一条「某月某日 那天的碎事」，不会把很久以前的琐碎事混进当前语境；
        • 同一件事说两遍不会记成两条（内容相近的会合并、更新）。

        计划（带准确时间，到点她会主动开口）

        • 你让她在某个时间做一件事（“明早八点提醒我吃药”），她会当场定一条计划，并自己换算成绝对时间；
        • 每条计划都有准确的到点时间，界面里显示倒计时；页面开着时由页面盯，页面关着时由常驻客户端盯；
        • 到点她会用自己口吻发一条消息（QQ 上发给主人），不需要你提醒；
        • 做完了、或你说不用做了，她会在回复里把对应计划标成完成。

        梗知识

        • 聊到新梗、黑话、你们的暗号，她会主动记进「梗知识」，不用你点按钮；
        • 另外每 25 分钟会把最近聊的内容过一遍，补记漏掉的梗；
        • 记错的可以手动删掉，也能自己加。

        日记

        「人设 → 日记」里是她自己写的日记：每天过 0 点会补写当天的，写的是那天你们聊了什么、她记住了什么、计划做完没有，以及她自己的心情。

        • 第一人称、口语、可以写乱一点，不写总结陈词；长短不限。
        • 页面开着时由心枕写；也可以在日记页点「现在写一篇」随时补一篇。
        • 每篇带日期和星期，可以单独删掉。

        名单

        「名单」分 QQ 和 B 站两套，互不影响。

        • 主人：最优先，永远会回；她不会叫你的 QQ 昵称，只叫你设的称呼。
        • 白名单：能拿到她的人设和记忆，像熟人一样聊。
        • 普通 / 黑名单：只回一句客套话；黑名单默认不回，且完全拿不到人设与记忆。
        隐私红线　只有白名单（含主人）会把人设和记忆带进提示词，其他人一个字都拿不到；出站消息还会过滤路径、密钥、邮箱这类内容。

        外接 · QQ（完整部署流程）

        QQ 靠 NapCat（一个跑在服务器上的 QQ 客户端）把消息转成 OneBot 11 协议，心枕通过 HTTP + WebSocket 收发。

        1. 起 NapCat 容器

        docker run -d --name napcat --restart always \
  -e TZ=Asia/Shanghai \
  -e ACCOUNT=2821744520 \
  -e NAPCAT_QUICK_PASSWORD='你的QQ密码' \
  -e NAPCAT_UID=0 -e NAPCAT_GID=0 \
  -p 127.0.0.1:3000:3000 -p 127.0.0.1:3001:3001 -p 6099:6099 \
  -v /opt/napcat/config:/app/napcat/config \
  -v /opt/napcat/qq:/app/.config/QQ \
  mlikiowa/napcat-docker:latest
        • 3000 = HTTP 接口，3001 = 事件 WebSocket，6099 = 自带 WebUI（扫码用）。
        • 配了 NAPCAT_QUICK_PASSWORD，掉线会自动用账号+密码登录，不用反复扫码；不配就只能扫码。

        2. 配置 NapCat 的网络

        打开 http://服务器:6099/webui，用 NapCat 的 token 登录，在「网络配置」里确认：

        HTTP 服务器       0.0.0.0:3000   token: 你的令牌
WebSocket 服务器  0.0.0.0:3001   token: 你的令牌

        3. 用 nginx 反代成同源

        页面和 NapCat 必须同源，否则浏览器会拦。

        location /qq/api/ { proxy_pass http://127.0.0.1:3000/; add_header Access-Control-Allow-Origin * always; }
location /qq/ws   { proxy_pass http://127.0.0.1:3001/; proxy_http_version 1.1;
                    proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; }

        4. 心枕里连上

        「外接 → QQ → NapCat 连接」：HTTP 接口填 http://你的域名:7863/qq/api，事件 WebSocket 填 ws://你的域名:7863/qq/ws，访问令牌填 NapCat 里那个。点「测试连接」，卡片上出现机器人昵称就成了。

        5. 建议同时开的开关

        • 第一句等 N 秒：对方连发几条时，攒够一轮再一起回（默认 6 秒，0 = 立刻回）。
        • 拆成几条：回复拆成 1~3 条发出去；群里最多 2 条。
        • 冷却 / 回复长度：同一个人两条回复之间的最小间隔、单条字数上限。
        • 看图片：真图片会走视觉模型；表情包不描述画面，只理解情绪。
        • 页面关着也回消息：交给服务器上的常驻客户端（见下文）。

        外接 · B 站

        不用桌面版了：B 站的请求现在由服务器上的常驻客户端代发，页面只跟同源的 /bili/ 说话。

        • 浏览器自己发 B 站请求会被跨域和风控（-412 / -352）同时拦住，所以在服务器上代跑；
        • 登录也在应用里完成：外接 → B 站 → 点「登录」，弹出二维码，用手机 B 站 App 扫一下，扫码结果直接存到服务器；
        • 登录态存在服务器的 /var/lib/xinzhen-bridge/bili.json（含 buvid3/buvid4 和 SESSDATA），换浏览器不用重登；
        • 能做的事：按关键词找视频、看视频信息和字幕、按你们聊过的话题刷一批视频、在她的日报里点评、发评论、看和回私聊。

        通道坏了怎么查

        curl -s http://127.0.0.1:9100/bili/status        # login:true 就是登着
curl -s -X POST localhost:9100/bili/get \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://api.bilibili.com/x/web-interface/view?bvid=BV1GJ411x7h7"}'

        返回 {"ok":true,"status":200,"json":{"code":0,…}} 就正常；code:-412 是风控，删掉 bili.json 里的 cookie 让程序重新取 buvid 即可。

        常驻客户端（页面关着也能回，也是自动重连的主要那一层）

        页面不开就收不到消息，所以服务器上常驻了一个「代替页面」的进程 xinzhen-bridge。它把所有保活、重连、补收的活都揽在自己身上，不需要额外装脚本、定时器或计划任务。

        它自己会做的事

        • 收消息 + 重连：常连 NapCat 的事件 WebSocket，断了按 3 秒起、最多 30 秒退避重连，页面关着也照收。
        • 登录巡检：每 45 秒查一次机器人是否还在线，结果写进 qqhealth.json，页面据此显示「在线 / 需要扫码」。
        • 掉线自救：发现登录失效，就调一次 root 帮手脚本重启 NapCat 容器（配了密码的会自动登回来），失败的话把二维码刷到 /qqlogin.png。
        • 替你回：页面上报「我在线」的租约一断，它就用你同步过来的人设、记忆、名单、计划回消息；你一打开页面，60 秒内自动交还，不会两边同时回。
        • 定时计划：每 30 秒扫一遍到点的计划，页面不在线时由它替你触发。

        怎么看它在不在干活

        systemctl status xinzhen-bridge          # 服务状态
journalctl -u xinzhen-bridge -n 50 -f    # 日志（连接、重连、掉线自救都会打）
curl -s localhost:9100/status            # connected / loginOk / 收到多少条 / 最近错误

        三层重连，各管一段

        • 页面里：心枕自己带着连接看门狗（12 秒连不上就掐掉重连、70 秒没心跳也重连、切回标签页会体检一次）—— 只管页面开着的时候。
        • 服务器上：xinzhen-bridge 负责页面没开的那段时间，以及机器人自己被踢下线的情况。
        • 登录彻底失效：这个只能扫码，页面顶上会出现红字提示和二维码链接。
        为什么不用单独的脚本　以前掉线重启是 qqguard.timer、二维码刷新是 cron、常驻收消息是 bridge，三套东西各记各的状态。现在全部收进 xinzhen-bridge 一个服务：一个日志、一份状态、一个自检接口。

        设置

        • 上下文长度：可填 128k、1m 或数字，超出就把最旧的消息丢掉。
        • 流式输出：开了就是字一个个冒出来；有些中转不支持，关掉更稳。
        • 数据：按角色导出 / 导入；换电脑前记得导。

        数据与隐私

        所有数据都存在你这台机器的浏览器里（换电脑、清缓存前记得导出）。设置 → 数据里有四个动作：

        导出

        • 当前 AI：只导这一个角色，包括形象、人设、记忆、关键词、梗知识、计划、日记、表情包、聊天记录、名单、外接设置和界面设置；
        • 全部数据：所有角色一起打包，换设备整个搬走用这个；
        • 格式：JSON（原样备份）或 Markdown（人设、记忆、梗、计划写成能读的文字，末尾附一段给心枕读的原始数据）。两种都能导回心枕；
        • 不含：模型接口（地址 / 密钥 / 模型名）和 NapCat 的接口密钥 —— 这些换机器要自己重填，也不会跟着文件外传。

        导入

        • 支持心枕导出的 .json / .md，也支持别人分享给你的备份；
        • 共存：当成新角色加进来，现有的不动（重名自动加序号）；
        • 覆盖：先清空本机的角色和数据，只留备份里的；
        • 导入时会保留你本机填好的模型接口，不会被备份里的空值冲掉。

        删除当前 AI 数据

        只删当前这个角色的一切（立绘、人设、记忆、关键词、梗、计划、日记、表情包、聊天记录），其它角色不受影响。按钮带 5 秒倒计时，点错了还来得及取消。

        软件里所有确认框都是同一套样式（居中卡片 + 取消 / 确认），不会跳浏览器自带的弹窗。

        常见问题

        她突然不回 / 收不到消息

        1. 看「外接 → QQ → 当前行为」有没有新记录；没有就是消息没进来。
        2. 打开 http://服务器:7863/webui/：如果要求扫码，说明机器人登录失效了，扫一下就好。
        3. 看 curl -s localhost:9100/status 的 connected 和 lastError。

        回复变成一大段

        把「拆成几条」的上限调大、「第一句等」调小；模型句子太少时也可能只出一条。

        接口报错 / 空回复

        推理模型（会先输出思考过程的那种）容易把 token 全花在思考上，换一个非推理模型试试。
